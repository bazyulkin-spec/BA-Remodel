# Публикация BA-Remodel в Google Play

Файлы рядом: `icon-512.png` (иконка страницы), `feature-1024x500.png` (баннер),
`privacy-policy.md` (политика конфиденциальности), `listing-ru.md` и `listing-en.md` (тексты).

---

## Часть 1. Ключ подписи (делается один раз)

Ключ — это то, чем подписываются все будущие обновления. Потеряешь — обновлять приложение
будет нечем, придётся публиковать новое. Храни копию вне GitHub.

1. В репозитории: **Settings → Secrets and variables → Actions → New repository secret**.
   Создай три секрета (значения придумай сам, запиши в надёжное место):
   - `KEYSTORE_PASSWORD` — пароль хранилища, минимум 12 символов
   - `KEY_PASSWORD` — пароль ключа (можно такой же)
   - `KEY_ALIAS` — короткое имя ключа, например `upload`
2. Вкладка **Actions** → workflow **Create upload keystore** → **Run workflow**.
3. Скачай артефакт `upload-keystore-PRIVATE`. Внутри `upload-keystore.jks` (сам ключ —
   сохрани его на диск и в облако) и `keystore-base64.txt`.
4. Открой `keystore-base64.txt`, скопируй всё содержимое одной строкой и создай ещё один
   секрет `KEYSTORE_BASE64` с этим значением.
5. Удали артефакт со страницы запуска (кнопка с корзиной) — приватный ключ не должен
   лежать в общем доступе. Через сутки он удалится сам.

## Часть 2. Релизная сборка

Actions → **Release AAB for Play** → **Run workflow**. На выходе два артефакта:
- `BA-Remodel-release-aab` — файл `.aab`, его и загружают в Play Console;
- `BA-Remodel-release-apk` — обычный APK для ручной проверки.

`versionCode` подставляется автоматически из номера запуска, так что каждая новая сборка
принимается магазином без ручных правок.

## Часть 3. Аккаунт разработчика

- Регистрация: play.google.com/console, разовый взнос 25 $.
- **Тип аккаунта решает многое.** Личный аккаунт, созданный после 13 ноября 2023 года,
  обязан пройти закрытое тестирование: не менее 12 участников, подключённых непрерывно
  14 дней, и только потом заявка на публикацию. Аккаунт на юридическое лицо от этого
  требования освобождён. Если есть оформленный бизнес — регистрируй на него, сэкономишь
  две недели и нервы.
- Понадобятся платёжный профиль и налоговые данные (для Израиля — реквизиты осек/компании).

## Часть 4. Создание приложения в консоли

1. **Create app**: название BA-Remodel, язык по умолчанию — русский или английский,
   тип «Приложение», платное/бесплатное — **бесплатное** (монетизация будет подпиской).
2. **Store listing**: короткое описание (до 80 символов) и полное — тексты в `listing-ru.md`,
   иконка `icon-512.png`, баннер `feature-1024x500.png`, минимум 2 скриншота телефона
   (сделай прямо в BlueStacks: план с раскладкой, декор по центру, вкладка отчёта).
3. **Privacy policy**: нужен публичный URL. Проще всего: в этом же репозитории
   Settings → Pages → включить GitHub Pages для ветки main, положить `privacy-policy.md`
   как `docs/index.md` — получится ссылка вида `https://<имя>.github.io/BA-Remodel/`.
4. **Data safety**: приложение хранит проекты только на устройстве, фото плитки не
   передаёт, аккаунтов нет. Отвечай: данные не собираются и не передаются третьим лицам.
   Когда добавим рекламу — форму придётся обновить (AdMob собирает идентификаторы).
5. **Content rating**: анкета, категория «Инструменты», возраст 3+.
6. **Target audience**: взрослые, не для детей.
7. **App access**: всё доступно без входа — так и указать.

## Часть 5. Закрытое тестирование

1. **Testing → Closed testing → Create track**, загрузить `.aab`.
2. Список тестировщиков: 12 и более почт Google. Родные, коллеги, знакомые мастера,
   чаты плиточников. Каждый должен **принять приглашение и установить приложение** —
   просто добавить почту недостаточно.
3. Ждать 14 дней подряд. Если число опустится ниже 12, отсчёт начнётся заново, поэтому
   лучше пригласить 15–18 человек с запасом.
4. Через 14 дней: **Dashboard → Apply for production access**, ответить на вопросы о
   тестировании и готовности. Проверка обычно занимает до недели.

Обновления во время теста заливать можно и нужно — стены, мебель и смета как раз
успеют доехать.

## Часть 6. Монетизация (после публикации)

- **Подписка**: Monetize → Products → Subscriptions, создать `pro_monthly` и `pro_yearly`.
  Затем подключаем Play Billing 9 в коде — это отдельный шаг разработки.
- **Реклама**: аккаунт AdMob, связать с приложением, получить App ID и блоки,
  добавить UMP-форму согласия. Выплаты приходят при накоплении 100 $.
- **Защита от копирования**: Play Console → App integrity → включить автоматическую защиту.
  Тогда пересланный APK предложит установить официальную версию из магазина.
